# 在 Windows 上运行用户中心

本教程使用 Docker 运行 MySQL 和 Redis，在 Windows 宿主机上运行两个 Go 进程。完成后，你可以调用注册、登录和用户详情接口。

本教程只适用于本地开发。数据库初始化脚本含 `DROP TABLE IF EXISTS`，只能导入新建的练习库或确认可以重建的空库。

## 准备工具

准备 Go 1.22 或可编译本项目的较新版本、PowerShell，以及已启动且切换到 Linux 容器模式的 Docker Desktop。预留 `33069`、`36379`、`1004`、`2004`、`4008`、`4009` 端口。

运行已有代码不需要先安装 goctl 或 protoc；仓库已包含生成代码。

1. 在 PowerShell 中进入项目并检查工具：

   ```powershell
   Set-Location E:\go\go-zero-looklook-main
   go version
   docker version
   docker compose version
   ```

   `docker version` 应同时显示 Client 和 Server。若提示找不到 `dockerDesktopLinuxEngine`，先启动 Docker Desktop，等待引擎就绪。

2. 下载仓库声明的依赖：

   ```powershell
   go mod download
   ```

   首次下载需要网络。这里只下载依赖，不用 `go mod tidy` 改写依赖文件。下载失败时先排查网络或配置适合你网络环境的 Go 模块代理。

## 启动 MySQL 和 Redis

1. 在项目根目录启动两个基础设施容器：

   ```powershell
   docker compose -f docker-compose-env.yml up -d mysql redis
   docker compose -f docker-compose-env.yml ps
   ```

   此命令只选择 MySQL 和 Redis，不启动整个日志监控环境。不要同时运行根目录 `docker-compose.yml` 中的 `looklook` 服务，否则可能出现两套业务进程和数据操作混用。

2. 查看启动日志：

   ```powershell
   docker compose -f docker-compose-env.yml logs --tail 80 mysql redis
   ```

   MySQL 初始化可能需要一段时间。容器处于运行状态不等于数据库已就绪；能成功执行下一节的 SQL 才能确认数据库可用。

## 初始化练习数据库

本节使用 Compose 中现有的 MySQL 容器。若 `data/mysql/data` 已有数据，实际 root 密码取决于数据库第一次初始化时的设置，后续修改 Compose 密码不会自动修改已有账户。

1. 将用户中心 SQL 复制到容器：

   ```powershell
   docker cp .\deploy\sql\looklook_usercenter.sql mysql:/tmp/looklook_usercenter.sql
   ```

2. 登录容器内的 MySQL：

   ```powershell
   docker exec -it mysql mysql -uroot -p
   ```

   按提示输入 `docker-compose-env.yml` 中 `MYSQL_ROOT_PASSWORD` 的值；已有数据时使用实际密码。

3. 在 MySQL 提示符中检查练习库：

   ```sql
   CREATE DATABASE IF NOT EXISTS looklook_usercenter
     CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   USE looklook_usercenter;
   SHOW TABLES;
   ```

   若存在 `user` 或 `user_auth` 且需要保留数据，跳过下一步导入，先确认表结构符合仓库 SQL。不要重新执行初始化脚本覆盖已有用户。

4. 仅在新库或允许重建的练习库中导入表结构：

   ```sql
   SOURCE /tmp/looklook_usercenter.sql;
   SHOW TABLES;
   ```

   结果应包含 `user` 和 `user_auth`。

5. 创建本地练习账号并授予用户中心库权限：

   ```sql
   CREATE USER 'looklook_dev'@'%' IDENTIFIED BY 'LooklookLocal2026!';
   GRANT ALL PRIVILEGES ON looklook_usercenter.* TO 'looklook_dev'@'%';
   EXIT;
   ```

   此账号用于连接 Docker 映射出来的数据库端口。若账号已存在，请使用已有账号的实际密码并同步下一节配置，不必重复创建。这里的密码是教程示例值。

## 创建本地配置

仓库默认配置使用容器地址 `mysql:3306`、`redis:6379`。宿主机进程应使用映射后的 `127.0.0.1:33069` 和 `127.0.0.1:36379`。

1. 在项目根目录创建本地配置目录：

   ```powershell
   New-Item -ItemType Directory -Force .\data\local | Out-Null
   ```

   `data/*` 已在 `.gitignore` 中，适合存放本机配置。

2. 创建 `data/local/usercenter-rpc.yaml`，写入以下内容：

   ```yaml
   Name: usercenter-rpc
   ListenOn: 127.0.0.1:2004
   Mode: dev
   JwtAuth:
     AccessSecret: looklook-local-learning-secret-2026
     AccessExpire: 86400
   Log:
     ServiceName: usercenter-rpc
     Mode: console
     Level: info
   Prometheus:
     Host: 127.0.0.1
     Port: 4009
     Path: /metrics
   Redis:
     Host: 127.0.0.1:36379
     Type: node
     Pass: G62m50oigInC30sf
     Key: usercenter-rpc
   DB:
     DataSource: "looklook_dev:LooklookLocal2026!@tcp(127.0.0.1:33069)/looklook_usercenter?charset=utf8mb4&parseTime=true&loc=Asia%2FShanghai"
   Cache:
     - Host: 127.0.0.1:36379
       Pass: G62m50oigInC30sf
   ```

   `Redis.Pass` 和 `Cache[].Pass` 必须与 Compose 的 Redis 密码一致。如果你修改过 Redis 配置，更新这两处。`Redis` 用于 RPC 配置及显式客户端，`Cache` 用于 Model 缓存，不要只改其中一处。

3. 创建 `data/local/usercenter-api.yaml`，写入以下内容：

   ```yaml
   Name: usercenter-api
   Host: 127.0.0.1
   Port: 1004
   Mode: dev
   JwtAuth:
     AccessSecret: looklook-local-learning-secret-2026
   Log:
     ServiceName: usercenter-api
     Mode: console
     Level: info
   Prometheus:
     Host: 127.0.0.1
     Port: 4008
     Path: /metrics
   WxMiniConf:
     AppId: local-unused
     Secret: local-unused
   UsercenterRpcConf:
     Endpoints:
       - 127.0.0.1:2004
     NonBlock: true
   ```

   两份配置的 `AccessSecret` 必须相同。`WxMiniConf` 仅用于满足配置结构，本教程不调用微信授权接口。配置省略了 `Telemetry`，因此无需启动 Jaeger。

   本地示例将令牌有效期设为一天。仓库默认值是 `31536000` 秒，两者不同是有意的；API 返回的过期时间是时间戳，不是有效期秒数。

## 启动两个 Go 进程

1. 在第一个 PowerShell 终端启动 RPC：

   ```powershell
   Set-Location E:\go\go-zero-looklook-main
   go run ./app/usercenter/cmd/rpc/usercenter.go -f ./data/local/usercenter-rpc.yaml
   ```

   预期出现 `Starting rpc server at 127.0.0.1:2004...`，且进程持续运行。此消息表示程序进入启动阶段，后续接口验证才能确认数据库和业务正常。

2. 在第二个 PowerShell 终端启动 API：

   ```powershell
   Set-Location E:\go\go-zero-looklook-main
   go run ./app/usercenter/cmd/api/usercenter.go -f ./data/local/usercenter-api.yaml
   ```

   预期出现 `Starting server at 127.0.0.1:1004...`，且进程持续运行。

3. 在第三个 PowerShell 终端验证端口：

   ```powershell
   Test-NetConnection 127.0.0.1 -Port 2004
   Test-NetConnection 127.0.0.1 -Port 1004
   ```

   两次的 `TcpTestSucceeded` 应为 `True`。RPC 的 `2004` 是 gRPC 端口，不是供浏览器访问的 HTTP 接口。

## 注册并登录用户

在第三个终端依次执行本节步骤。后续示例复用此终端中的变量。

1. 为练习用户构造请求：

   ```powershell
   $baseUrl = 'http://127.0.0.1:1004'
   $credentials = @{
       mobile = '13800138000'
       password = 'LearnGoZero2026!'
   } | ConvertTo-Json
   ```

2. 注册用户：

   ```powershell
   $register = Invoke-RestMethod -Method Post -Uri "$baseUrl/usercenter/v1/user/register" -ContentType 'application/json' -Body $credentials
   $register | ConvertTo-Json -Depth 5
   ```

   预期返回 HTTP 200，响应结构如下。令牌和时间戳会随实际请求变化：

   ```json
   {
     "code": 200,
     "msg": "OK",
     "data": {
       "accessToken": "实际签发的 JWT",
       "accessExpire": 1792200000,
       "refreshAfter": 1792156800
     }
   }
   ```

   重复注册同一手机号会失败。如果之前已注册，直接进行登录，或换用未注册的练习手机号。

3. 使用相同账号登录：

   ```powershell
   $login = Invoke-RestMethod -Method Post -Uri "$baseUrl/usercenter/v1/user/login" -ContentType 'application/json' -Body $credentials
   $token = $login.data.accessToken
   $login.code
   ```

   预期输出 `200`，且 `$token` 非空。注意成功业务码是 `200`，不是 `0`。

## 查询当前用户

1. 携带登录令牌请求用户详情：

   ```powershell
   $authHeaders = @{ Authorization = "Bearer $token" }
   $detail = Invoke-RestMethod -Method Post -Uri "$baseUrl/usercenter/v1/user/detail" -Headers $authHeaders -ContentType 'application/json' -Body '{}'
   $detail | ConvertTo-Json -Depth 5
   ```

   预期 `code` 为 `200`，`data.userInfo.mobile` 为注册时的手机号，`data.userInfo.id` 大于 `0`。该接口是 **POST**，请求体不需要用户 ID，身份来自 JWT。

2. 省略令牌再次调用：

   ```powershell
   Invoke-RestMethod -Method Post -Uri "$baseUrl/usercenter/v1/user/detail" -ContentType 'application/json' -Body '{}'
   ```

   预期出现 HTTP 401，PowerShell 会报告请求失败。这是鉴权验证的预期结果。JWT 中间件的错误响应不一定使用业务层的 `code/msg` 包装。

3. 可选：查看 API 指标：

   ```powershell
   (Invoke-WebRequest -Uri 'http://127.0.0.1:4008/metrics').Content
   ```

   预期为 Prometheus 文本指标。指标端口与业务接口端口不同。

## 停止练习环境

在运行 API 和 RPC 的两个终端分别按 `Ctrl+C`，然后停止本教程启动的两个容器：

```powershell
docker compose -f docker-compose-env.yml stop mysql redis
```

此命令保留数据库文件。下次启动后直接登录已有用户，不需要重新导入 SQL。
